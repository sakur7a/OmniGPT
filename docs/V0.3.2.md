# OmniGPT 0.3.2 — Reply-copy and Markdown math compatibility

## Motivation

The v0.3.1 patch updated conversation export, not the page's **native reply-copy button**.
That button can write text via the Clipboard API without firing a browser `copy` event,
and ChatGPT's source commonly wraps inline math in backslash-parenthesis delimiters.

## What changed

- A scoped capture handler recognizes `button[data-testid="copy-turn-action-button"]`
  under a conversation turn. For a supported assistant response with math, it copies
  the rendered response to the clipboard using the selected math style.
  Plain-text replies and unrecognized layouts keep their native behavior.
- Selected raw math text is converted on Ctrl+C when a supported formula renderer
  is not present. Copying code or typing in an editor still stays native.
- The OmniGPT panel's **Copy Markdown** converts recognized math delimiters from
  API-sourced text into Markdown form. **Downloaded exports are unchanged** and retain
  the source text from the API.
- The delimiter conversion skips inline code, fenced and indented code, and escaped
  literal markers. The formula body (e.g., `5\\leq6\\leq7`) is preserved.
- Users who previously selected `LaTeX` in **More options → Formula copy** will
  still get backslash-parenthesis math when copying rendered formulas until they
  select `Markdown`. The selected style is intentionally persistent.

## Boundaries

The selector is based on ChatGPT's browser DOM, not a published API contract.
Unknown action buttons or math renderers without recoverable TeX may still use
ChatGPT's original copy behavior. There is no global interception of
`navigator.clipboard`, `fetch` or `MutationObserver`, and no background scanning.

CI tests cover string conversion, representative native copy-action markup,
real Chromium clipboard writes, keyboard selection, the option persistence, and
mocked API-sourced Markdown copy. They are not a real logged-in ChatGPT end-to-end test.
