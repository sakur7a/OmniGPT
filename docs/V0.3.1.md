# OmniGPT v0.3.1 — ChatGPT Web conversation API compatibility

ChatGPT Web switched its stored-conversation detail endpoint around August 2026 from
`GET /backend-api/conversation/{id}` (a complete `mapping` tree) to
`GET /backend-api/conversations/{id}?include_has_versions=true&num_turns=100`
(a paginated `messages[]` list).

## Changes

- Prefer the plural conversation endpoint, retaining the singular mapping endpoint only as a 404/405 fallback.
- Follow `page_info.has_previous_page` via `before=page_info.start_cursor` until the oldest page, rather than silently exporting only the last 100 messages.
- Deduplicate overlapping page-boundary messages by ID; keep the newest page's copy and the chronological order.
- Accept direct and wrapped flat message items, preserve the active branch when parent pointers are provided, and exclude hidden reasoning and control messages.
- Reject missing/repeating cursors, empty intermediate pages, missing pagination flags, mismatched conversation IDs and unfinished responses, instead of labeling a partial result as complete.
- Preserve the existing explicit partial-warning DOM fallback and the cancellation, retries, progress indicators and concurrency bounds.
- Add mocked endpoint regressions for flat history, pagination, anomalies, auth-compatible legacy fallback and abort behavior.

## Limitations

The `/backend-api/` routes are **undocumented browser-internal endpoints** and can change without notice.
These regressions cover representative simulated API responses. They are not an authenticated
end-to-end test of a live ChatGPT account. A browser session with access to the user's
actual conversation list remains necessary to verify end-to-end exports.

Large exports still depend on the current account's history list and do not cover
unlisted conversations or binary attachments. If API retrieval fails for a current chat,
the exported DOM fallback is explicitly marked partial. If an archive item fails,
the archive records the failed item rather than silently omitting it.
