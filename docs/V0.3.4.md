# OmniGPT 0.3.4 — Current-page math copying

## Confirmed failure

The signed-in ChatGPT page inspected on 2026-10-21 exposed message bodies through
`data-content-search-unit-key` and interaction containers through
`data-talvt-turn-state`. Its reply Copy action was an accessible Copy button in
`.turn-action-controls`. The legacy message and copy-button selectors all matched
zero elements, although OmniGPT 0.3.2 was loaded with Markdown formula style.

Both real selection Ctrl+C and the native reply-copy action reproduced
backslash-parenthesis math output. Existing unit tests and older browser fixtures
passed because they still represented the earlier markup.

## Changes

- Recognize current message units and scoped reply actions while retaining legacy
  markup. Unknown actions, code-copy buttons and editable fields retain native
  behavior.
- Copy all assistant body blocks in the interaction, excluding its user prompt,
  reasoning blocks, action controls and other replies.
- Protect raw TeX before prose escaping, so formulas still convert beside code
  and beside rendered math. Code content remains unchanged. Display formulas
  preserve quote and list prefixes.
- Preserve explicit LaTeX style, plain-text-only clipboard output, and the
  existing on-demand runtime. No new grants, network interception, global
  Clipboard API patch or continuous page observer is introduced.

The stable version `0.3.4` is numerically newer than the local
`0.3.3-local.1` / `0.3.3-local.2` test builds. The userscript namespace and GitHub
Raw update/download URLs remain unchanged.

## Regression coverage

```sh
npm run check
python test/browser-regression.py
python test/browser-v030.py
python test/browser-current-dom.py
```

The Node suite covers delimiter normalization, code protection and idempotence,
along with the existing export checks. The new browser suite covers current and
legacy markup, both copy paths, inline/display math, mixed raw/rendered formulas,
unrelated and unselected code, multiple body blocks, quotes/lists, repeated copy,
ordinary text, editors and unknown actions. It is included in the existing CI.

Browser suites use real Chromium keyboard and clipboard operations against
representative DOM fixtures. They are not authenticated ChatGPT E2E tests.
The original failure was reproduced in a signed-in Edge/Tampermonkey session;
successful repaired copy on that session has not yet been established. Firefox,
Violentmonkey and desktop paste-target behavior remain outside this verification.
